# SDL3 gamepad subsystem

Source: `libsdl-org/SDL` at commit `137944b` (2026-10-09); crate `sdl3-sys`
0.7.2 bundles SDL 3.4.18. License: zlib.

## Canonical model

`include/SDL3/SDL_gamepad.h`:

- **Positional face buttons**: `SOUTH`, `EAST`, `WEST`, `NORTH` ("Bottom face
  button (e.g. Xbox A button)"). Labels are a separate query
  (`SDL_GAMEPAD_BUTTON_LABEL_A/B/X/Y/CROSS/CIRCLE/SQUARE/TRIANGLE`).
- Other buttons: `BACK`, `GUIDE`, `START`, `LEFT_STICK`, `RIGHT_STICK`,
  `LEFT/RIGHT_SHOULDER`, `DPAD_*`, `MISC1..MISC6`, four paddles
  (`RIGHT_PADDLE1`, `LEFT_PADDLE1`, `RIGHT_PADDLE2`, `LEFT_PADDLE2`) and
  `TOUCHPAD`. `MISC1` is documented as Xbox Series share, PS5 mic, Switch Pro
  capture, Luna mic, Stadia capture: one slot, several meanings.
- Axes: `LEFTX`, `LEFTY`, `RIGHTX`, `RIGHTY`, `LEFT_TRIGGER`, `RIGHT_TRIGGER`.
- Gamepad types: `STANDARD`, `XBOX360`, `XBOXONE`, `PS3`, `PS4`, `PS5`,
  `NINTENDO_SWITCH_PRO`, three Joy-Con types, `GAMECUBE`, `STEAM`.

## Joystick GUID

`SDL_CreateJoystickGUID` (`src/joystick/SDL_joystick.c`), 16 bytes,
little-endian 16-bit fields:

| Bytes | Field |
|-------|-------|
| 0-1 | bus (`0x03` USB, `0x05` Bluetooth, `0xFF` virtual, `0x00` unknown) |
| 2-3 | CRC16 of `"<vendor name> <product name>"` (or product name), may be 0 |
| 4-5 | vendor ID |
| 6-7 | 0 |
| 8-9 | product ID |
| 10-11 | 0 |
| 12-13 | version |
| 14 | driver signature: `'h'` HIDAPI, `'x'` XInput, `'w'` WGI, `'g'` GameInput, `'r'` RawInput, `'m'` MFi, `'v'` virtual |
| 15 | driver-dependent data |

Without a VID, bytes 4-13 hold the product name instead. So **the same pad
gets a different GUID per bus, per OS backend and per firmware version**,
which is exactly why GameControllerDB entries are per platform.

## Backends and their priority

`SDL_joystick_drivers[]` is an ordered list. HIDAPI comes first ("Highest
priority driver for supported devices"), then (Windows) GameInput, RawInput,
DirectInput/XInput, WGI, WinMM, then Linux evdev, IOKit, MFi, Android,
Emscripten...

Deduplication is `SDL_JoystickHandledByAnotherDriver(driver, vid, pid,
version, name)`: before a lower-priority backend opens a device it asks every
higher-priority backend `IsDevicePresent(vid, pid, version, name)`; if one says
yes, the device is skipped. The Linux, IOKit, RawInput, XInput, DirectInput
and WGI backends all call it.

## HIDAPI drivers

`src/joystick/hidapi/` has user-space protocol drivers for: GameCube adapter,
Amazon Luna, NVIDIA Shield, PS3 (+ third-party, Sixaxis), PS4, PS5, Stadia,
Steam Controller, Steam Deck, HORI Steam, Steam "Triton", Nintendo Classic,
Joy-Cons, Switch Pro, Switch 2, Wii, Xbox 360 (wired, wireless receiver, Big
Button), Xbox One/Series (GIP), 8BitDo, Flydigi, GameSir, Zuiki, SInput,
Logitech wheels (`lg4ff`). It also parses HID report descriptors
(`SDL_report_descriptor.c`).

Each driver is behind a hint that defaults to `SDL_JOYSTICK_HIDAPI` (default
on), except Xbox, which defaults to off on Windows (`SDL_JOYSTICK_HIDAPI_XBOX`).

## Hints relevant to coexistence

| Hint | Effect |
|------|--------|
| `SDL_JOYSTICK_HIDAPI`, `SDL_JOYSTICK_HIDAPI_<DRIVER>` (`PS4`, `PS5`, `SWITCH`, `SWITCH2`, `XBOX`, `STEAM`, `8BITDO`, `GIP`, `SINPUT`, ...) | Enable/disable HIDAPI drivers globally or per family |
| `SDL_HIDAPI_IGNORE_DEVICES` | `0xVVVV/0xPPPP,...` list ignored by SDL's HID enumeration (`0x0000` PID = whole vendor) |
| `SDL_GAMECONTROLLER_IGNORE_DEVICES` / `..._EXCEPT` | Same format, applied to gamepads; `@file` form supported |
| `SDL_JOYSTICK_ENHANCED_REPORTS` | Default `1`. Enhanced reports enable rumble/effects on Bluetooth PlayStation pads and gyro on Switch pads, **but break DirectInput for non-SDL apps and cannot be undone on PlayStation pads without power-cycling**. `auto` only switches when the app uses the features |
| `SDL_HIDAPI_ENUMERATE_ONLY_CONTROLLERS` | Avoid opening keyboards/mice (macOS permission prompts) |
| `SDL_JOYSTICK_RAWINPUT`, `SDL_JOYSTICK_WGI`, `SDL_JOYSTICK_GAMEINPUT`, `SDL_XINPUT_ENABLED`, `SDL_JOYSTICK_DIRECTINPUT`, `SDL_JOYSTICK_IOKIT`, `SDL_JOYSTICK_MFI` | Enable/disable OS backends |
| `SDL_HIDAPI_UDEV`, `SDL_HIDAPI_LIBUSB` | Linux device discovery and libusb use |

## Steam Input awareness

`SDL_steam_virtual_gamepad.c` reads the file named by the
`SteamVirtualGamepadInfo` environment variable (set by Steam) to map Steam's
virtual pads back to the real controller's VID, PID and type, and decides
whether to swap face buttons.

## Linux evdev backend details (needed by the GameControllerDB importer)

`ConfigJoystick` in `src/joystick/linux/SDL_sysjoystick.c` numbers buttons
starting at `BTN_JOYSTICK` up to `KEY_MAX`, then codes below `BTN_JOYSTICK`;
hats come from `ABS_HAT0X..ABS_HAT3Y` pairs; the remaining `ABS_*` codes are
axes in code order. When no mapping exists, SDL guesses one; its comment lists
three trigger conventions: `ABS_HAT2Y/HAT2X` (Linux gamepad spec),
`ABS_BRAKE/ABS_GAS` (Android, many Bluetooth pads), `ABS_Z/ABS_RZ` (older Xbox
and PlayStation).

## Implications for anygamepad

- Keep the positional model plus a label layer (matches SDL3, the Linux
  gamepad spec, gilrs and the W3C standard mapping).
- Reuse SDL's arbitration idea: an ordered provider list where a provider
  claims a device by identity before lower ones open it (C12).
- When anygamepad owns a device natively, feed `SDL_HIDAPI_IGNORE_DEVICES` /
  `SDL_GAMECONTROLLER_IGNORE_DEVICES` to SDL. Default
  `SDL_JOYSTICK_ENHANCED_REPORTS=auto` so merely opening a PlayStation pad does
  not change its report mode for other apps (C13).
- Our identity (C2) must be able to compute SDL GUIDs (bus, CRC16, VID, PID,
  version, driver signature) to look up GameControllerDB entries and to
  correlate with SDL-provider devices.
- Store the bus, the backend and the version as separate identity fields, never
  only a GUID.
