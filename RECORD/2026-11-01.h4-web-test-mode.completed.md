# H4: Test mode in the web app

- Status: completed
- Roadmap: ROADMAP/2026-10-31/ (task ID: H4)

## Goal

The web tester's test mode (ADR 0008, owner's flow of 2026-10-31): a list
of controllers; picking one shows the ways to connect it; a pad connected
without picking is shown as detected, to confirm or to change; a session
runs a test plan with the library's runner; the anonymous test report is
reviewed, saved in the browser and downloaded.

## Decisions

- The `.wasm` budget goes from 160 to 224 KiB (gzip). Reason: the test
  mode adds about 56 KiB (152.1 KiB before, 210.0 after): the runner, the
  catalog and plans with their decoding, the test report's scrubbing,
  validation and review. Measured with twiggy, the cost is spread over the
  feature, not one dependency. `serde_json` was taken out (the report goes
  to JavaScript as an object and `JSON.stringify` writes it), saving about
  20 KiB. Alternative left for later: build the test mode as a second
  module loaded when the tab opens, keeping the tester at its old size.
- The test mode lives in the same page as the tester and shares its
  devices and frame loop. Reason: one Gamepad API reader and one WebHID
  owner; a pad connected while the tester shows is detected all the same.
- While a WebHID pad is under test, the test mode reads it
  (`feedTest`) and the tester does not (`owns()`). Reason: reading takes
  the reports, which are the session's evidence.
- Results and outcomes cross to JavaScript with the JSON-compatible
  serializer. Reason: the measurements are maps, which the default
  serializer turns into `Map`s that `JSON.stringify` drops. Absent values
  then arrive as `null`, which the page treats as absent.
- "Nothing happens" fails the step rather than marking the control
  missing. Reason: the pad has the control; that the page cannot read it
  is a finding, and "Not on this pad" would put a wrong missing button in
  the report.
- The progress bar is a `<progress>` element. Reason: the page's CSP
  forbids inline styles.
- A saved session keeps its file name when downloaded afterwards; other
  sessions of the same configuration and day get `-2`, `-3`...
