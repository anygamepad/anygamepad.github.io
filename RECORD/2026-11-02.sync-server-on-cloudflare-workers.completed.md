# Sync server on Cloudflare Workers and D1

- Status: completed (deployment is the owner's, P5)
- Roadmap: ROADMAP/2026-11-01/ (task IDs: P2, P5, P6; status notes in
  place)

## Goal

The owner accepted on 2026-11-02 the advice of
`RECORD/2026-11-02.web-test-page-theme-icons-and-sending.completed.md`: a
Cloudflare Worker in Rust with D1 as the online database of the web app's
activity logs and test reports. Write the ADR and the server (P2) with the
two endpoints the web app's settings send to.

## Done

- **ADR 0009** (accepted): Worker in Rust (`workers-rs`), D1 in the EU,
  the rate limiting binding keyed by an HMAC of the address, D1 Time
  Travel as the backups, no request logs, `wrangler deploy` by the owner.
  It supersedes the framework, storage and hosting of ADR 0006 (status and
  index updated).
- **`apps/server`**, crate `anygamepad-server` (workspace member):
  - `api.rs`: `POST /v1/test-reports` (validated by
    `TestReport::from_json`, stored re-serialized as compact JSON next to
    its query columns, deduplicated by SHA-256, `201 {"id"}` or `200`),
    `DELETE /v1/test-reports/{id}`, `POST /v1/activity-logs`
    (`201`/`200` for a retry, `403` when the page load's log was started
    with another token), `DELETE /v1/activity-logs/{session}`, `GET /`.
    Every write needs `Authorization: Bearer <32-64 hex>`; the store keeps
    its SHA-256. CORS for `ALLOWED_ORIGINS` only (`403` for other origins;
    no `Origin` is accepted, for other apps), `no-store`, `nosniff`.
    Errors `400`, `401`, `404`, `405`, `413`, `415`, `429`, `500` (the
    storage's cause never reaches the answer).
  - `activity.rs`: a part's typed header (format, library, page,
    environment, session, part, day, dropped events; unknown fields
    refused) and its events checked by shape (names, `t`, nesting, sizes),
    every text scrubbed with `anygamepad_report::privacy::scrub_text`
    (made public for this), except `data` and `fingerprint` when they have
    their hexadecimal shape.
  - `day.rs`: UTC days and the retention cut-off.
  - `runtime.rs` (`wasm32` only): the `fetch` handler (rate limit on POST
    and DELETE, body size, then `api::handle`), D1 as the `Store` (one
    batch per operation), and the daily `scheduled` deletion of activity
    logs older than `ACTIVITY_LOG_RETENTION_DAYS` (180).
  - `migrations/0001_initial.sql`, `wrangler.toml`, `package.json`
    (wrangler 4.153.0), `README.md` with the owner's deployment steps.
- **Web client** (`src/sync.ts`): a token per page load's log and per test
  report, kept in `localStorage` (`anygamepad.sync.sent`, 1,000 at most);
  "Delete what this browser sent" in the settings withdraws them all and
  starts a new log; refused parts (4xx) are dropped, passing failures
  (network, 429, 5xx) retried.
- **Privacy**: the policy page (dated 2026-11-02) gains "Sending to the
  anygamepad database" (what, where, why, how long, withdrawing) in place
  of "No server yet"; `docs/privacy/README.md` gains the withdrawal texts,
  the new storage key, retention rows and server rules matching the
  Worker.
- **CI** (`build.yml`): the web build reads the repository variable
  `ANYGAMEPAD_SYNC_URL`; a `server` job runs `tests/smoke-sync.mjs`, and
  deployment waits for it. `smoke.mjs` accepts a build that names a
  server.
- **Tests**: 11 native tests (routing, CORS, tokens, deduplication,
  withdrawal, activity log checks and scrub, days, rate limit keys).
  `apps/web/tests/smoke-sync.mjs` (`npm run test:sync`): the real Worker
  under `wrangler dev` on a fresh local D1, the site built naming it, a
  Quick session in Chrome with sending on; D1 holds the report as sent
  with its columns, and the log scrubbed; withdrawing empties both.
  Checked by hand on the same Worker: duplicate reports, another token's
  part (`403`), deletion, the 180-day cron, and `429` (with CORS headers)
  after 30 writes in a minute.
- Checked: fmt, clippy (workspace native and `wasm32`), the server's
  tests, Rust 1.85 natively and on `wasm32` without the server, `tsc`,
  build, size, both smoke tests and the sync smoke test in Chromium.
- Size (gzip): JS 80.8 KiB; the budget goes from 80 to 88 KiB (below).

## Decisions

- **Tokens are made by the app, not returned by the server.** Reason: a
  part retried after a lost answer still carries the right token, the
  server needs no randomness, and the app knows the token before it
  sends. The server rules were reworded to say so.
- **The first part of a page load's log sets its token**; later parts with
  another token are refused. Reason: session IDs are not secrets in the
  data, and nobody else can add to or withdraw someone's log.
- **A duplicate test report adds its sender's token**, so either sender can
  withdraw it. Reason: identical reports are rare, and nobody loses the
  right to withdraw what they sent.
- **Activity log texts are scrubbed, not refused.** Reason: one odd text
  must not block a log the page cannot fix; the redactions are counted.
- **Activity logs are kept 180 days** (`ACTIVITY_LOG_RETENTION_DAYS`),
  test reports until withdrawn. Reason: logs serve debugging and the next
  releases' detection; test reports are the lab's evidence. Proposed here:
  the owner may change the variable and the two texts that state it.
- **workers-rs 0.8.7 needs Rust 1.91**: the MSRV job (1.85) checks the
  server natively and skips its `wasm32` build. Reason: no workers-rs
  release supports 1.85 (0.8.6 declares 1.75 but needs wasm-streams 0.6,
  which needs 1.88); the Worker is built by the project with stable Rust,
  not by the library's users.
- **The JS budget goes from 80 to 88 KiB.** Reason: the settings, the
  sending client and the withdrawal took the bundle to 80.8 KiB; the
  budget keeps its 10% margin.
- Wrangler 4.153.0, not an older pin: earlier versions carry undici
  advisories (`npm audit`).

## Open questions

- Whether sent test reports and logs are dedicated to the public domain
  (CC0) and published in dumps like shared reports: the switch's text says
  nothing about it, so for now they are not.
- The Workers Paid plan ($5 a month) for 30 days of restore points instead
  of 7: the server rules ask for 30; the policy says "up to 30 days".
- A log part already on its way when the person withdraws can recreate
  that page load's log on the server; it is then deleted by its retention.
