# Release: web smoke jobs apply the release version

- Status: completed
- Roadmap: ROADMAP/2026-11-01/ (no task ID: fix to the build and release
  workflows, see `RECORD/2026-10-13.build-and-release-workflows.completed.md`)

## Goal

The 0.0.5 release run failed in `build / web smoke (firefox)` and
`build / web smoke (webkit)`:

```
AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
'0.0.5' !== '0.0.4'
    at apps/web/tests/smoke.mjs:560:10
```

Make the release's smoke jobs pass.

## Done

- Cause: `smoke.mjs` checks that a saved report's `source.app_version`
  (the WebAssembly crate's `CARGO_PKG_VERSION`) equals the version in
  `apps/web/package.json`. In a release run, the `web` job applies the new
  version before building, but the `web-smoke` job did not: it ran the
  0.0.5 site it downloads from the `web` artifact against a checkout that
  still held 0.0.4. Push and pull request runs pass because they have no
  version input. The Chrome smoke test in the `web` job passed because that
  job applies the version.
- `.github/workflows/build.yml`: `web-smoke` now has the same "Apply the
  release version" step (`if: inputs.version`) as every other job that
  checks out the tree, before `npm ci`.
- Verified: actionlint 1.7.7 on `build.yml` and `release.yml`;
  `version.mjs set 0.0.5` in a throwaway worktree writes 0.0.5 to
  `apps/web/package.json` (18 places, `check` agrees). The workflow change
  itself only runs on GitHub.
- The failed release pushed nothing (no `v0.0.5` tag, `main` unchanged),
  as designed: the `release` job needs `build`.

## Decisions

- Apply the version in `web-smoke` rather than relax the test's version
  check. Reason: the check is right (the report must carry the app's
  version), and every job that checks out the tree should see the version
  being built, so later jobs that read the tree do not hit the same problem.
