# C2: Device identity, fingerprint and provider trait

- Status: completed
- Roadmap: ROADMAP/2026-10-10/ (task ID: C2)

## Goal

Define how a device is identified (shared with D1 and P1), its fingerprint,
the SDL GUID computation, the raw input layer providers deliver, and the
`Provider` trait every input source implements (ADR 0002).

## Done

- `anygamepad-model`:
  - `identity`: `Os` (with `Os::current()`), `ProviderKind`, `Backend`
    (evdev, hidraw, Windows HID, XInput, WGI, GameInput, DirectInput, IOKit
    HID, GameController, Gamepad API, WebHID), `BrowserEngine`, `Browser`
    (engine + major version), `WebGamepad` (`Gamepad.id` and `mapping`
    verbatim), `DescriptorHash`, `Fingerprint`, `DeviceIdentity`
    (`new`, `from_gamepad_api`, `fingerprint`, `sdl_guid`), and
    `GamepadApiId::parse` for every `Gamepad.id` format in
    `docs/research/06-browser-gamepad-api.md`.
  - `sdl`: `SdlGuid` (`create` as `SDL_CreateJoystickGUID`, `ids` as
    `SDL_GetJoystickGUIDInfo`, `without_crc`, parse/display as in
    GameControllerDB), SDL bus constants, `sdl_bus(Transport)`.
  - `raw`: `RawSource` (index, evdev code, HID usage, or an already canonical
    button/axis), `RawAxisInfo`, `RawLayout`, `RawState` (allocated once per
    device, filled in place), `Hat` (with HID hat switch and evdev hat axis
    conversions).
  - `OutputCommand` (rumble, trigger rumble, lightbar, player number).
  - Deterministic hashes (`hash.rs`): FNV-1a 64 and CRC-16/ARC with
    reference test vectors.
- `anygamepad::provider`: `Provider` trait (`kind`, `update`, `info`,
  `open`, `close`, `poll`, `send`), `DeviceId`, `ProviderEvent`, `Access`
  (shared, exclusive, observe-only), `DeviceInfo`, `DeviceLocation`,
  `ProviderError`. A scripted provider in the tests checks the trait works
  as `dyn Provider`.
- Verified locally: fmt, clippy (native, all features, wasm32), tests,
  rustdoc with `-D warnings`, `cargo +1.85` check and tests.

## Decisions

- Identity and raw types live in `anygamepad-model` (with serde/schemars),
  the `Provider` trait in `anygamepad`. Reason: profiles (D1) and reports
  (P1) need the data types without depending on providers.
- OS device paths and container keys are in `DeviceLocation`, which is
  runtime only: no serde, redacted `Debug`. Reason: Windows instance IDs and
  Linux `uniq` values can contain serial numbers and Bluetooth addresses
  (AGENTS.md: never collect or log them); `DeviceIdentity` stays safe to put
  in reports by construction.
- Fingerprint = FNV-1a 64 over a documented, versioned field encoding
  (`anygamepad-fingerprint-v1`), excluding the browser version; values pinned
  in tests and cross-checked with an independent Python implementation.
  Reason: it is stored in reports (P2 deduplication), so it must be identical
  in WebAssembly and native code and across releases; `std::hash` is not.
- 64-bit hashes serialize as 16-digit hex strings in human-readable formats.
  Reason: JSON numbers lose precision above 2^53 in JavaScript.
- Browser version is the major version only. Reason: enough for remapping
  changes, and less identifying.
- Providers always deliver raw elements; backends that already normalize
  (XInput, SDL gamepad, gilrs) use `RawSource::Button`/`Axis` sources, so the
  mapping engine (C3) has a single path. Motion, touch and power arrive
  already in canonical units in `RawState`.
- "Detected mode" is not an identity field: it is the result of profile
  matching (C8) and of the wizard (W4), not something a provider reads.
- `DescriptorHash` is FNV-1a 64 of the raw HID report descriptor (no
  normalization). Reason: simple and identical everywhere; collisions are
  unlikely at the expected number of descriptors.

## Open questions

- Claims and SDL exclusions (ADR 0002 items 3-4) are not in the trait yet;
  C12 decides whether they need a trait method (e.g. "exclude these
  identities before enumerating") or live in the SDL3 provider's constructor.
- Bluetooth product names can be renamed by users on some OSes; P1/P3 must
  decide whether `product_name` needs filtering before upload.
- The serde form of `RawSource` (externally tagged) is a placeholder for D1,
  which may prefer compact strings in TOML (`"evdev:0x130"`).
