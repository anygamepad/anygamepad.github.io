# Tester hint for the DualSense in Chromium on macOS

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (task ID: W2, follow-up)

## Goal

The owner's DualSense never shows in the live tester in Chrome on macOS
(docs/research/06-browser-gamepad-api.md, "DualSense in Chrome on macOS").
The page only said "press one of its buttons", which does not help there.
Tell Chromium users on macOS why, while no gamepad shows.

## Done

- `apps/web/src/tester.ts`: `missingGamepadHint(environment)` returns the
  explanation for the Blink engine on macOS, `null` elsewhere; `TesterView`
  gains `hint`, set once at start.
- `App.html`: the empty state is a block with the usual message and, when
  there is one, the hint (`.message.hint`, muted, solid border).
- Smoke test: no hint in the default context; in a context with a macOS
  Chrome user agent, the footer reads `blink N on macos`, the hint shows, and
  it goes away once a gamepad shows.
- Verified locally: `npm run wasm`, `npm run build` (includes `tsc`),
  `npm run size` (wasm 74.2, JS 35.1, CSS 1.4 KiB gzip), smoke test in
  Chromium 141. Screenshots at 1100 px (light) and 390 px (dark).

## Decisions

- The hint is set from the user agent (engine and OS), not after a timeout
  without gamepads. Reason: a timeout cannot tell "no gamepad connected" from
  "a gamepad the browser hides"; the cause is known for this combination.
- It names the DualSense only. Reason: only the DualSense is confirmed
  (owner's test and motorust); the DualShock 4 and others are unverified.
- It suggests Safari without promising it works. Reason: Safari reads
  PlayStation pads through GameController, but it has not been tried with
  the owner's pad yet.
