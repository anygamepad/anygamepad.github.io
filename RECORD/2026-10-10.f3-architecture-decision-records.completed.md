## Decisions

- ADRs stay `proposed` until the owner accepts them. Reason: F3 is done when
  ADRs are accepted, and the stack choices are the owner's.
- jq79 for the web UI (owner decision). Usage rules recorded in ADR 0005:
  import components through `jq79/vite`; enable `safeEval` so the CSP needs
  no `'unsafe-eval'` (GitHub Pages only allows a `<meta>` CSP); keep logic in
  `.ts` modules type-checked by `tsc`, because the plugin only strips types
  from component scripts; pin the version (pre-1.0).
- Server stack split into ADR 0006. Reason: the owner was only asked about
  the web framework; an ADR has a single status, and P2 (the first server
  task) is far away, so it can be accepted later without blocking anything.
- F3 counts as completed with 0004 and 0006 still `proposed`. Reason: the
  tasks F3 unblocks now (C1, C2, W1) only need 0001-0003 and 0005; 0004 is
  needed before A1 (after M2) and 0006 before P2.
