# W5: Normalized view (mapping engine + profiles)

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (task ID: W5)

## Goal

Display the canonical output produced by the mapping engine (C3) and the
compile-time embedded device database (D4) next to raw values in the web tester,
and highlight disagreements where the active profile contradicts what the user
confirmed in the guided mapping wizard (W4).

## Done

1. Integrated `Database::embedded()` and `Mapper` in `crates/anygamepad-wasm`:
   - `Gamepads` holds `db: Database` and an active `mappers: BTreeMap<DeviceId, Mapper>` table populated on `open()`.
   - `info()` retrieves the best matching profile via `Mapper::from_database(&self.db, &info.identity, &info.layout)`.
   - Populated `profile_name`, `capabilities`, `family`, `face_layout`, and `canonical` (via `canonical_layout_from_mapping`).
   - For standard layout pads with extra buttons (index >= 17), `canonical_layout_from_mapping` preserves standard button mappings and augments `capabilities.buttons`.
   - `state()` evaluates the canonical state via `mapper.apply(raw, &mut state)`, plus extra standard buttons when applicable.
2. Web UI (`apps/web`):
   - Created collapsible `.normalized-values` section above raw values in `LiveView`.
   - Displayed active profile name in a `.profile-badge`.
   - Displayed mapped canonical buttons and axes with live visual meters and track bars.
   - Implemented disagreement detection between active profile mappings (`info.canonical`) and wizard results (`identified`).
   - Highlighted disagreeing controls with `.disagreement` class and a `⚠️` warning badge displaying a descriptive mismatch tooltip in both the raw values list and canonical controls list.
3. Bundle Size Optimization:
   - Configured `opt-level = "z"` for release builds in root `Cargo.toml`.
   - Verified that `.wasm` gzip size remains under the 128 KiB budget (123.9 KiB).
4. Testing:
   - Added end-to-end assertions in `apps/web/tests/smoke.mjs` verifying the normalized view and badge on `DUALSHOCK`.
   - Added disagreement test on `DUALSHOCK3` confirming that when a user maps disagreeing controls in the guided wizard (swapping South and East), disagreements are detected and highlighted.
   - All smoke tests and workspace tests pass.

## Decisions

- **Embedded Database Lookup**: `Mapper::from_database` is called during `info()` and `open()`. Only `Mapper` is stored in `mappers` (not cloning `Profile`) to keep memory usage minimal.
- **WASM Size Optimization**: Release profile uses `opt-level = "z"` in workspace `Cargo.toml` to stay comfortably within the 128 KiB `.wasm` gzip budget.
- **Standard Layout Fallback**: Browsers report standard gamepads with 17 standard buttons and optionally extra buttons (e.g. DualShock 4 touchpad click at button 17). `canonical_layout_from_mapping` falls back to `standard::button(i)` for standard layout controllers with extra buttons.
- **Disagreement Highlighting**: Both raw inputs (buttons/axes) and canonical controls display a ⚠️ badge with a tooltip detailing the mismatch between wizard confirmation and profile mapping.
