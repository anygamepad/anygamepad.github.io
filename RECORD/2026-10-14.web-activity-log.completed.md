# Web tester: activity log

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (no task ID: owner request, 2026-10-14;
  serves the real-device checks of W3 and C15)

## Goal

A button in the web tester that downloads a log of the activity it
detected, so the owner can share a session for analysis (first case: the
DualSense in Chrome on macOS).

## Done

- `apps/web/src/activity.ts` (`ActivityLog`): kept in the tab from page
  load, downloaded as JSON (`anygamepad-activity-log-v1`): library version,
  environment, start time, duration and events in time order. Times are
  milliseconds since the page loaded.
- Events: `session` (environment, WebHID support, hint shown);
  `gamepad_added`/`removed` (identity, fingerprint, family, face layout,
  counts, outputs, canonical layout); raw `button` and `axis` changes;
  `canonical_buttons` (the pressed set, when it changes); `hid_chooser`,
  `hid_added` (identity, transport, collections), `hid_opened`,
  `hid_removed`; `hid_report_sample` (the first report of each ID and
  length, in hex); `hid_report_form`; `hid_decode_error` (first time, then
  `hid_decode_error_repeats` with a count); decoded `canonical_axis`,
  `touches` and `power`; actions (`vibration_test`, `hid_switch_to_full`,
  `hid_recording`); `rate` per pad every 10 s; `page_hidden`/`visible`;
  `error`, `hid_message` and `page_error`.
- Analog values are logged when they move 0.05 or reach 0 or ±1; at most
  the newest 20,000 input events are kept (`dropped_input_events` counts
  the others); device events are always kept.
- The frame loop now reads every Gamepad API pad once a frame (for the log),
  and the live view reuses that read. A "Download the activity log" panel
  under WebHID, always shown (also when the Gamepad API fails).
- The recording download and the log share a `saveJson` helper.
- Smoke test: after the whole session, the downloaded log has the session,
  every pad added and removed, raw and canonical inputs, the vibration
  tests, the WebHID flow (chooser, samples of reports `0x01`/9 and
  `0x31`/77, reduced then full form, switch, recording, power, touches,
  removal), in time order. Passed 4 times in a row in Chromium.
- `apps/web/README.md`: the file table was stale (`diagram.ts`); now lists
  every module.
- Size (gzip): JS 53.4 KiB of 64 (51.7 before).

## Decisions

- The log is built in TypeScript, not in the library. Reason: it is a
  debugging aid of the tester; the device report (P1) is the library's
  structured format and may take what proves useful from these logs.
- Always on, bounded, never sent anywhere. Reason: the interesting session
  is the one that just happened; the file leaves the browser only when the
  viewer downloads and shares it.
- Raw values at 60 Hz (the frame loop), not the 4 ms sampler. Reason:
  serializing every pad 250 times a second costs more than it shows; human
  presses last longer than a frame.
- Canonical axes are not logged for Gamepad API pads. Reason: their
  mapping is fixed (standard layout), so the raw axes say the same.
- No personal data: identities as the library builds them (no serial
  numbers or addresses by construction), input reports only (the
  calibration feature report read by the switch is not logged).
