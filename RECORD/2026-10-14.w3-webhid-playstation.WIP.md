# W3: WebHID mode with PlayStation decoding

- Status: WIP
- Roadmap: ROADMAP/2026-10-14/ (task ID: W3)

## Goal

Let Chromium users connect a pad through WebHID: raw reports and report
structure for any game controller, and PlayStation pads decoded by C15, so
the owner's DualSense shows in Chrome on macOS.

## Done

- `anygamepad-wasm` (`HidDevices`): `info()` adds `family`, `face_layout`,
  `transport` (from the report sizes), `decoded` and `touchpad`; `poll()`
  drains a device's queue, decodes PlayStation reports and returns the
  count, the newest report, the newest decoded input and the last decode
  error, plus every report on request (to record);
  `switchToFullReports()` reads the calibration report only. `DeviceInfo`
  (Gamepad API) adds `family` and `face_layout`. `ts/check.ts` covers the
  new API.
- Web app: a WebHID box (Chromium only) opens the chooser for game
  controllers; WebHID pads join the list. A decoded pad hides its Gamepad
  API twin (same VID/PID). Its view: reports per second, report form, a
  warning and a button to switch a Bluetooth pad to the full report, the
  family drawing with touchpad fingers, touchpad, motion (raw counts) and
  battery panels; folded, the newest raw report, a decode error, "Record 2
  seconds" (downloads JSON: identity, report structure, reports) and the
  report structure.
- The macOS hint now points to WebHID as well as Safari.
- Smoke test: a fake `navigator.hid` with a Bluetooth DualSense that sends
  the reduced report, then the full one with its CRC after a feature
  report is read. Covers the chooser filters, twin hiding, decoding, the
  switch (only `0x05` read), panels, the recording file and disconnection.
  Passes 8 times in a row in Chromium 141; Firefox and WebKit run in CI.
- Sizes (gzip): wasm 85.6 KiB, JS 40.3 KiB, CSS 2.1 KiB (W2: 74.2, 35.1,
  1.4).
- A device that fails to poll (unplugged between two samples) is skipped
  rather than stopping the frame loop.

## Decisions

- The full-report switch is a button next to a warning, never automatic.
  Reason: it changes the pad for every program until it is turned off;
  the user decides (on macOS the system has already switched it).
- `poll()` replaces per-frame `reports()`, and returns every report only
  when asked. Reason: serializing every report every frame is waste; the
  recording needs them, the live view does not.
- Recordings hold the VID/PID, product name, family, transport, report
  structure and reports, nothing else. Reason: they are the fixtures C15
  needs, and the owner's direction is local files first (2026-10-14).
- WebHID pads have no vibration test. Reason: output reports are C7's.
