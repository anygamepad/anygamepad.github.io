# W9: Test mode as a separately loaded WebAssembly module

- Status: completed
- Roadmap: ROADMAP/2026-11-01/ (task ID: W9)

## Goal

The test mode's runner, catalog, plans and report format in a WebAssembly
module of their own, loaded when the Test mode tab first opens, so that
the tester's module goes back within its 160 KiB budget (owner decision,
2026-11-01; open question of H4).

## Done

- New crate `crates/anygamepad-wasm-testing` (`publish = false`): what
  `anygamepad-wasm/src/testing.rs` had (`catalogModels`, `labUnits`,
  `testPlans`, `TestSession`), plus `identify(device)`,
  `checkChoice(device, ...)`, `startTest(device, setup)`, and
  `TestSession.feed(input, now)`, `takeCommands()`, `added(device, now)`.
  It depends on `anygamepad` without default features (no providers).
- `anygamepad-wasm`: no runner (the `testing` feature is off); new
  `test_bridge` module with `TestDevice` (device report, outputs, whether
  input reports come along, unreadable buttons) and `TestInput` (raw and
  canonical state, input reports); `Gamepads.testDevice()`/`testInput()`
  and `HidDevices.testDevice()`/`testInput()` replace `identify`,
  `checkChoice`, `startTest`, `feedTest` and `testReconnected`. Values
  cross as plain objects (the JSON-compatible serializer).
- Web app: `test-mode.ts` loads the module with `loadTesting()` (a dynamic
  import, once), takes it in `TestMode`'s constructor, describes pads with
  `testDevice()`, feeds `testInput()` once a frame and sends
  `takeCommands()` through the tester's `send()` (also when a session
  ends, so a stopped output stops). `tester.ts` creates the test mode when
  its tab first opens; the page shows "Loading the test mode…" (stage
  `loading`) until then.
- Build: `npm run wasm` builds both modules (`wasm:tester`,
  `wasm:testing`) into `src/wasm/` and `src/wasm-testing/` (ignored).
  `scripts/check-size.mjs` has a budget per module: the tester's `.wasm`
  160 KiB, the test mode's 176 KiB. CI type-checks both modules'
  declarations together (`ts/check.ts`) and uploads the test mode's
  bindings as `wasm-testing-bindings`; a release adds
  `anygamepad-wasm-testing-vX.Y.Z.zip`.
- `tests/smoke-test-mode.mjs` also checks that the test mode's module is
  fetched only once its tab opens.
- Measured (gzip -9): the tester's module 155.5 KiB (211.0 with the test
  mode, 152.1 before H4); the test mode's module 160.7 KiB; JavaScript
  76.9 of 80 KiB (the second module's glue).
- Checked: fmt, clippy (workspace; wasm32), workspace tests, the wasm
  browser tests build, Rust 1.85 (native and wasm32), `tsc` of both
  declarations, the web build and size, both smoke tests in Chromium.

## Decisions

- The two modules exchange values, not objects. Reason: two WebAssembly
  instances share no memory; a `Gamepads` or `TestSession` of one is
  meaningless to the other. The tester's module stays the only reader of
  the devices, as in H4.
- The test mode's module is 160.7 KiB, more than the 59 KiB the test mode
  added to the single module. Reason: it has its own copy of the standard
  library, the allocator, serde and serde-wasm-bindgen, the model, and the
  device report's deserializer (the report crosses as a value). Most
  visits now load 55 KiB less; opening the Test mode tab costs 160.7 KiB
  more, once. Its budget, 176 KiB, leaves room for the catalog to grow.
- A path dependency on `anygamepad` in the new crate. Reason: Cargo 1.85,
  the MSRV, refuses `default-features = false` on a workspace dependency
  whose workspace entry has them on.
- A WebHID pad the library does not decode cannot be described
  (`testDevice()` throws, as `startTest()` did), so it is not detected
  through its WebHID row; its Gamepad API row is listed and detected.
- The test mode's bindings get their own artifact and release zip. Reason:
  the `anygamepad-wasm` zip keeps its layout.

## Open questions

- Firefox and WebKit run the smoke tests in CI only (Playwright's builds
  cannot be downloaded here).
- If the test mode's module grows, a lighter device report crossing (only
  what the session reads) would cut its deserializer.
