# A3: Collection mode

- Status: WIP
- Roadmap: ROADMAP/2026-10-14/ (task ID: A3)

## Goal

Device reports (P1) from the desktop app: data the browser cannot see,
one report file per device in the app's data folder (ADR 0007), shared
through the same GitHub issue form as the web app after showing it, with
explicit consent (P3).

## Done

- `apps/desktop/src/collection.rs`: `build_report` (desktop source, host
  OS and kernel release, one view per device with profile, capabilities
  and the HID report descriptor from sysfs; scrubbed and validated),
  file names by VID/PID and fingerprint (one file per device), a report
  store (save through a temporary file, list newest first, delete only
  inside the folder), the issue form URL with its title, opening files and
  folders with the system's app.
- `apps/desktop/src/collection_page.rs`: the first-start text and buttons
  of `docs/privacy/README.md` ("Start collecting", "Open the folder");
  then a "Collect reports" switch that writes a report for every
  controller that connects; per connected controller what it is and its
  mode (the report's user statement) and save/update; the saved reports
  with Share, Open the file and Delete (asks "Delete this report file?");
  the share view with the consent texts, the whole report, redactions,
  the privacy link, "Copy and open the issue form", "Cancel", "Open the
  file".
- Settings `collection_started`, `collecting`; data folder per OS
  (`$XDG_DATA_HOME/anygamepad/reports`, `%APPDATA%\anygamepad\reports`,
  `~/Library/Application Support/anygamepad/reports`).
- `docs/privacy/README.md`: the desktop variants of two texts.
- Checked under Xvfb with the demo pad and clicks (xdotool): consent,
  automatic report file, list, share view. Validation caught two real
  inconsistencies on the way (descriptor hash vs included descriptor,
  the demo pad's unknown OS), both fixed. Tests: report building,
  scrubbing, store.

## Decisions

- The report's descriptor hash is recomputed from the descriptor it
  includes. Reason: `validate` requires them to match, and the bytes are
  read when the report is written.
- One file per device, replaced when recorded again. Reason: ADR 0007's
  "one report file per device"; the fingerprint changes when what the
  device reports changes, so a different view gets a new file.
- Collection mode opens devices in shared access like the device list.
  Observe-only (no handshakes) across every provider comes with C12.

## Open questions

- The guided mapping wizard (W4) is not in the desktop app yet, so
  reports carry no confirmed mapping.
- Only the native provider's view; other providers' views (SDL3, gilrs)
  come with C13/C14 and C12.
- Not tried with real controllers; Windows and macOS have no provider
  yet (C5, C6).
