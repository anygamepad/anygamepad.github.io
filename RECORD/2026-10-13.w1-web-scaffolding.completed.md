# W1: Web app scaffolding and WASM build pipeline

- Status: completed
- Roadmap: ROADMAP/2026-10-10/ (task ID: W1)

## Goal

Create the web app in `apps/web` (Vite + TypeScript + jq79, ADR 0005) on
top of `anygamepad-wasm`, with a build pipeline that compiles the bindings
with wasm-pack, a bundle size budget, previews from CI, and deployment of
the built site (only) to GitHub Pages.

## Done

- `apps/web`: Vite 8.3.4, TypeScript 6.0.3, jq79 0.7.4 (exact versions,
  `package-lock.json`). The page shows the library version, the browser and
  OS, and the connected gamepads (name, VID:PID, mapping, buttons/axes,
  rumble), read every frame through `Gamepads`. Logic in `src/tester.ts`
  (type-checked), rendering in `src/App.html`.
- `npm run wasm`: wasm-pack 0.15 release build of `anygamepad-wasm`, then
  `wasm-opt -Oz` from binaryen 132 (npm). Workspace release profile:
  `lto = true`, `codegen-units = 1`.
- Builds carry a Content Security Policy `<meta>` first in `<head>`:
  `script-src 'self' 'wasm-unsafe-eval'`, `style-src 'self'`, no
  `'unsafe-eval'` or `'unsafe-inline'` (jq79 `safeEval: true`).
- `npm run size`: gzip budget per type, wasm 128 KiB, JS 64 KiB, CSS
  16 KiB. Now: 73.3, 32.4 and 0.6 KiB.
- `npm run test:smoke` (playwright-core 1.63, the machine's Chrome): the
  built site loads under its CSP without console errors or warnings, the
  version and environment render, and a fake standard gamepad appears
  (VID:PID parsed) and disappears. Checked to fail when `safeEval` is off.
- CI `.github/workflows/web.yml`: wasm build, type-check and build, size
  budget, smoke test, `dist/` as an artifact on every run, and deployment
  of `dist/` to GitHub Pages on pushes to `main`.
- Found with the smoke test and fixed in `anygamepad::web`: the haptics
  externs (`vibrationActuator`, `effects`, `type`) now `catch`. A getter
  that threw unwound through `Gamepads::update` and left the object
  borrowed, so every later call failed ("recursive use of an object").
- Verified locally: clean `npm ci`, wasm build, build, size, smoke test
  in headless Chromium 141; the Rust checks and browser tests of C11.

## Decisions

- wasm-opt runs from the npm `binaryen` package (132, pinned) with
  `wasm-opt = false` in wasm-pack's metadata. Reason: wasm-pack 0.15
  downloads binaryen 117 (2024) by itself, older than the wasm features
  Rust enables by default; the npm copy is pinned in the lockfile.
- Release profile LTO with one codegen unit. Reason: 4.5% smaller wasm
  after wasm-opt (73.4 vs 76.8 KiB gzip); `opt-level` `s`/`z` were larger.
- Previews are the built site as a workflow artifact (14 days), served
  locally with `npx vite preview`. Reason: GitHub Pages hosts one site per
  repository; hosted previews need another host and its secrets (owner
  decision, see open questions).
- The CSP `<meta>` is injected by a Vite plugin in builds only, before
  every script and stylesheet. Reason: the dev server injects inline scripts
  and styles; a policy only governs what comes after it.
- `assetsInlineLimit: 0`. Reason: an inlined asset becomes a `data:` URL,
  which `script-src 'self'` refuses (jq79's precompiled scripts included).
- The smoke test fakes gamepads with objects whose prototype is
  `Gamepad.prototype` and whose members are own properties. Reason: Chrome
  has no test hooks for the Gamepad API, and the provider checks
  `instanceof Gamepad`; this runs the real path from the page to Rust and
  back.
- TypeScript 6.0.3 rather than 7.x (the new native compiler). Reason: the
  same version as the bindings check in CI; move both together later.
- Vite 8.3.4, the latest patch. Reason: releases on every Vite branch on
  2026-10-06 look like a coordinated security fix.
- W1 shows the device list only; the live view is W2.

## Open questions

- Owner action before merging: set the repository's Pages source to
  "GitHub Actions" (Settings, Pages), or the `deploy` job on `main` fails.
  Merging then publishes this page at <https://anygamepad.github.io>.
- Hosted PR previews (Netlify, Cloudflare Pages, ...) need an account and
  a token: owner decision.
- Safari is not tested; the smoke test runs Chrome only.
- The size budget will need raising when the profile database is embedded
  (D4), with the reason recorded.
