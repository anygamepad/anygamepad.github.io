# C15: PlayStation input decoder

- Status: WIP
- Roadmap: ROADMAP/2026-10-14/ (task ID: C15)

## Goal

Decode the input reports of the DualShock 4, DualSense and DualSense Edge
into the canonical state, sans-IO, so W3 can show these pads over WebHID
(Chromium on macOS never exposes the DualSense through the Gamepad API).

## Done

- `anygamepad-model`: `Family` (DualShock 3, DualShock 4, DualSense,
  DualSense Edge, Switch Pro, Xbox) from VID/PID, XInput or the names
  Safari's GameController gives; `Family::face_layout()`. The Gamepad API
  id parser now keeps the name of Safari's `"<name> Extended Gamepad"`.
- `anygamepad::protocol`: CRC-32 for Bluetooth reports;
  `protocol::playstation`: `Model`, `decode()` for USB (`0x01`), Bluetooth
  reduced (`0x01`, 9 bytes) and full (`0x31` DualSense, `0x11` DualShock 4,
  CRC checked; DualSense audio payloads skipped), buttons, sticks (Y up),
  triggers, touch points, battery, raw IMU counts and sensor clock;
  `transport_from_collections()` (504 bits USB, 616 bits Bluetooth);
  `CALIBRATION_REPORT` (`0x05`).
- Tests on reports built by hand for every form, hat directions, power
  states, CRC check value and corruption, unknown reports, transport from
  report sizes; family and Safari id tests.
- Verified locally: fmt, clippy (native, wasm32, model with all features),
  workspace tests, rustdoc with `-D warnings`, `cargo +1.85` checks.

## Decisions

- Motion stays raw (`RawImu`), `GamepadState.motion` stays empty. Reason:
  the canonical model promises SI units, which need the pad's calibration
  (C7); nominal scales would look right and be wrong.
- `decode()` tells the report form from the ID and length, not from a
  transport argument. Reason: one Bluetooth pad sends both forms, and the
  form changes at run time (after the switch).
- `Family` lives in the model crate, with its rules marked as a stopgap.
  Reason: drawings and glyphs need it now; device profiles (D4), built from
  collected reports, are meant to replace the rules (owner, 2026-10-14).
- The DualSense Edge's function and back buttons are not decoded. Reason:
  their bits are not confirmed by any source read so far.
- The Safari name parsing changes the product name (and so the
  fingerprint) of Safari GameController pads. Reason: the suffix is not part
  of the name; no report has been collected yet.

## Open questions

- Every layout comes from research note 09 (daidr's tester), SDL (reduced
  reports) and `hid-playstation` (DualShock 4 battery and touch) without
  being checked on a device. The DualSense feature-set CRC prefix (`0x53`
  vs `0xa3`) is not needed yet.
- `Family::from_name` names other than the DualSense's are unconfirmed.
