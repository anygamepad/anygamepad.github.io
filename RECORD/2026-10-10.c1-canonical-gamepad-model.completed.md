# C1: Canonical gamepad model

- Status: completed
- Roadmap: ROADMAP/2026-10-10/ (task ID: C1)

## Goal

Define the canonical gamepad model in `anygamepad-model`, following the
accepted ADR 0001: positional controls, label layer, axis conventions, SI
units, touch, power, transport, outputs and capability sets.

## Done

- `crates/anygamepad-model`:
  - `Button` (25 positional buttons from ADR 0001 + `Extra(ExtraButton)`,
    up to 32 extra buttons) and `ButtonSet` (`u64` bit set).
  - `Axis` (sticks `[-1, 1]` with Y positive = up, triggers `[0, 1]`),
    `AxisSet`, `Stick`.
  - Label layer: `ButtonLabel`, `FaceLayout` with `XBOX`, `PLAYSTATION`,
    `NINTENDO` and `UNKNOWN` presets.
  - `motion`: `Vec3`, `MotionSample` (timestamp in µs, gyro rad/s, accel
    m/s²), `Sensor`/`SensorSet`, `STANDARD_GRAVITY`, and the device frame
    documented in the module docs.
  - `TouchPoint` (normalized, top-left origin), `TouchpadInfo`
    (resolution, max fingers), `MAX_TOUCH_POINTS` = 4.
  - `Power`/`PowerState` (SDL-like states + optional percent), `Transport`
    (USB, Bluetooth, BLE, dongle).
  - `Output`/`OutputSet` (rumble, trigger rumble, HD rumble, lightbar,
    player LEDs, adaptive triggers), `Rumble`, `TriggerRumble`, `Rgb`.
  - `Capabilities` (buttons, axes, sensors, touchpads, outputs, battery)
    with a `standard()` preset matching the W3C standard mapping.
  - `GamepadState`: `Copy`, fixed size; axis setters clamp (NaN to 0).
  - Every enum has a stable snake_case name (`as_str`, `FromStr`,
    `Display`); `ParseNameError`.
  - Optional features `serde` and `schemars` (implies `serde`).
- Tests: unit tests per module, serde/postcard/JSON Schema integration tests
  (`tests/serde.rs`), crate doc example.
- CI: clippy and tests of the model with all features (native), clippy with
  all features on wasm32, MSRV check with all features.
- Verified locally: fmt, clippy (native, all features, wasm32), tests,
  rustdoc with `-D warnings`, `cargo +1.85 check` with and without features.

## Decisions

- `FaceLayout` is a struct of four `ButtonLabel`s with preset constants, not
  a closed enum of families. Reason: ADR 0001 says the label table is data
  in the profile database, so a new family with known labels needs no code
  change.
- `Extra` buttons carry an `ExtraButton` newtype checked at construction
  (`Button::extra(n)`), not a raw `u8`. Reason: an out-of-range index cannot
  exist, so `ButtonSet` never drops or panics on it.
- Serde: human-readable formats (TOML, JSON) use the snake_case names; binary
  formats (postcard) use bit indices and raw set bits. Reason: readable
  profiles and reports, and a small embedded profile blob (bundle size risk);
  the blob is rebuilt with the library (ADR 0003), so indices only need to be
  stable within one version.
- Device frame copied from SDL3 (+X right, +Y up out of the face, +Z towards
  the player; accelerometer includes gravity). Reason: SDL is the widest
  provider (C13) and GameControllerDB/SDL-based data can be imported without
  converting axes.
- `Share` stays distinct from `Select`: the DualShock 4 `Share` button is
  `Select` (position), `Share` is the Xbox Series share button (ADR 0001).
- Paddles: `1` is upper, `2` is lower (Xbox Elite P1 = `RightPaddle1`,
  P2 = `RightPaddle2`, P3 = `LeftPaddle1`, P4 = `LeftPaddle2`).
- HD rumble and adaptive triggers are capability flags only; their command
  types belong to the protocol drivers (C7). Reason: their parameters are
  device-specific and not needed before C7.

## Open questions

- Analog (pressure-sensitive) face buttons, as on the DualShock 3, are not
  modelled; add axes for them if reports show demand.
- `GamepadState` deserialization does not re-clamp axis values; acceptable
  while only tests and reports deserialize states.
- TypeScript types for the web bindings (`tsify`, ADR 0005) are added in C11.

## Next steps

- C2 (device identity, fingerprint, `Provider` trait) and W1 (web
