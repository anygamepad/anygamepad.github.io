# H2: Controller catalog and lab inventory format

- Status: completed
- Roadmap: ROADMAP/2026-10-31/ (task ID: H2)

## Goal

The data the test modes run on (ADR 0008): a catalog of controller models
as sold, with their controls, modes and the ways to connect each mode, and
the format of the lab inventory (the owner's units and machines, F4).

## Done

- `anygamepad_db::catalog`: `Model` (ID `<vendor>/<model>`, vendor, name,
  `generic`, family, face `labels`, `Controls`, `Mode`s, notes), `Mode`
  (ID, printed name, `kind`, `how_to`, optional own `controls`,
  `Connection`s), `Connection` (transport, `how_to`, `ExpectedIdentity`s),
  `ExpectedIdentity` (vendor/product ID, name, OS, backend, driver,
  descriptor hash; `matches`, `specificity`), `Catalog` (unique IDs,
  `get`), validation, TOML read/write (`toml` feature), JSON Schema
  (`schemars` feature).
- `anygamepad_db::lab`: `Inventory` (`[[unit]]`, `[[machine]]`), `Unit`
  (code, model, notes), `Machine` (code, OS, version, browsers, notes),
  `Code` (1 to 16 ASCII letters, digits and hyphens), validation against
  the catalog, TOML, JSON Schema.
- `Catalog::embedded()` and `Inventory::embedded()`: the build script reads
  `data/controllers/` (checking every ID against its path) and
  `data/lab/inventory.toml` (empty inventory when the file does not
  exist, checked against the catalog), and embeds them with postcard.
- `ControllerMode` moved from `anygamepad-report` to `anygamepad-model`
  (re-exported by `anygamepad-report`), so catalog modes and device reports
  share it; `data/reports/schema.json` regenerated (the enum lost its
  per-variant descriptions, values unchanged).
- `data/controllers/`: README with the format, `schema.json`, 13 models:
  the generic types (`xinput`, `playstation`, `switch-pro`, `hid`),
  DualSense, DualSense Edge, DualShock 4 (two revisions), DualShock 3,
  Switch Pro Controller, Xbox 360 (wired and wireless), Xbox Series.
- `data/lab/`: README (codes, privacy), `schema.json`,
  `inventory.example.toml`. No real inventory: that is F4.
- The web build publishes the schemas at `/schema/controller.json` and
  `/schema/inventory.json`.
- Tests: unit tests (IDs, modes, connections, texts, codes, identities,
  inventory validation, postcard round trip); `tests/catalog.rs` (schemas
  up to date, every model valid and at its path and round-tripping, the
  embedded catalog equal to the files, generic types present, catalog IDs
  agreeing with `Family::from_ids`, the example inventory and both README
  examples valid). Checked: fmt, clippy (workspace, db/model/report with
  all features, db on wasm32), workspace tests (265 passed), Rust 1.85.

## Decisions

- A catalog model is separate from a device profile. Reason: a product
  with modes is not a mapping of one identity (ADR 0008).
- `ExpectedIdentity` rather than the profile `MatchRule`. Reason: the
  connection gives the transport (some APIs cannot tell it), SDL GUIDs and
  browser mappings are not product facts, and `MatchRule` skips
  serializing fields, which postcard cannot read back.
- No `skip_serializing_if` in catalog and inventory types. Reason: the
  embedded copy is postcard, which needs every field; TOML omits `None`
  on its own.
- Generic models carry no identities; detection reaches them by family
  (H10).
- DualShock 4 as two models (CUH-ZCT1 `05c4`, CUH-ZCT2 `09cc`). Reason:
  two products a collector tells apart, with different identities.
- Xbox Series over Bluetooth is `bluetooth_le`; its dongle connection has
  no identity yet (the Xbox Wireless Adapter needs `xone` on Linux).
- Connection instructions are short English texts; specifics the owner
  knows better (third-party mode combinations) come with F4.
- The real inventory is not committed. Reason: whether it is public is
  still the owner's call (RECORD of the plan); the build embeds it only
  when `data/lab/inventory.toml` exists.

## Open questions

- Product names per OS are not in the catalog yet: identities are VID/PID
  only, from the family rules; test reports will add names, drivers and
  descriptor hashes.
- The DualShock 3 Bluetooth instructions and the DualSense Edge's Fn
  buttons need a check on real pads.
