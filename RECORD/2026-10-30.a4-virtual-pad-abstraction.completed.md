# A4: Virtual pad abstraction and emulated profiles

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (task ID: A4)

## Goal

A `VirtualPad` trait and the emulated devices the desktop app offers (Xbox
360, DualShock 4, DualSense, Switch Pro Controller), each with its identity,
HID descriptor and canonical-to-output mapping, for A5, A7 and A8 to move
the bytes.

## Done

- `anygamepad-virtual`:
  - `Target` (stable names `xbox360`, `dualshock4`, `dualsense`,
    `switch_pro`, `FromStr`), its `Family`, its `VirtualIdentity` (VID/PID,
    `bcdDevice`, Linux device name) and `Target::create(index)`.
  - `VirtualPad` (sans-IO): `report_descriptor()`, `capabilities()`,
    `input_report(&GamepadState)`, `output_report(&[u8]) ->
    Vec<OutputCommand>`, `feature_report(id)`. Reports carry their report
    ID first.
  - `descriptor`: a HID report descriptor builder (crate-private) and
    `reports()`, which lists the reports a descriptor declares with their
    sizes (A5's UHID needs them).
  - Xbox 360: the 20-byte input packet (XInput state); rumble and ring
    light packets to `Rumble` and `PlayerNumber`. No descriptor (not HID).
  - DualShock 4 (`054c:09cc`) and DualSense (`054c:0ce6`), USB form: input
    report `0x01` (sticks, triggers, hat, buttons, touchpad, IMU, sensor
    clock, battery, counter); output `0x05` / `0x02` to rumble, light bar
    and (DualSense) player number; calibration, pairing and firmware
    feature replies. Descriptors with the real pads' report IDs, sizes and
    usages (504-bit input).
  - Switch Pro (`057e:2009`), USB form: input `0x30` (buttons by position,
    12-bit sticks, battery); player lights from subcommand `0x30`.
- Tests: unit tests per pad, and `tests/playstation.rs`, which decodes every
  emulated PlayStation report with C15's decoder (buttons, axes within one
  step, touch, power, IMU counts and clock), checks reply and report sizes
  against the descriptors, and that C15's `transport_from_collections`
  sees a USB pad.
- Verified: `cargo fmt`, `cargo clippy --workspace --all-targets -D
  warnings`, the crate on wasm32, `cargo test --workspace`, rustdoc with
  `-D warnings` for the crate, `cargo +1.85 check --workspace`.

## Decisions

- Sans-IO pads, bytes moved by the platform outputs. Reason: same split as
  the input protocols (C15); one encoding serves UHID, ViGEmBus and
  `IOHIDUserDevice`, and is testable without devices.
- USB form only. Reason: every output (UHID, ViGEmBus, IOHIDUserDevice)
  can present a USB device, which avoids Bluetooth CRCs and report-mode
  switches; a cable also explains a battery that is always charged.
- Descriptors are built to match the real pads' structure, not copied
  byte for byte. Reason: no recorded descriptor in the repository to copy;
  drivers that match the VID/PID read reports by ID and size, which the
  tests check. A5 compares them with real pads' descriptors.
- One nominal motion calibration for every virtual PlayStation pad (16
  counts per °/s, 8192 counts per g), served in the calibration feature
  report. Reason: the host scales raw counts with what the pad reports, so
  a consistent pair is exact whatever real pads report.
- The pairing feature report gives a made-up address
  (`02:61:67:00:00:<index>`, locally administered). Reason:
  `hid-playstation` refuses a pad without one; AGENTS.md forbids handling
  real addresses, and none is read or stored.
- `input_report` drops what a target lacks (no mute on the DualShock 4, no
  trigger axes on the Switch Pro, whose ZL/ZR are the trigger buttons).
  Reason: mapping a source pad onto a target is the app's job (C3, A2).
