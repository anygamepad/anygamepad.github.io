# Web: test mode page, theme icons and the sending switch

- Status: completed
- Roadmap: ROADMAP/2026-11-01/ (follow-ups to H4 and W9; the client side
  of P6 ahead of P2; status notes added in place)

## Goal

Owner requests of 2026-11-02 on the web app:

1. Advice on an online database for the web's activity log and test
   results, with a settings dialog where sending is turned on.
2. The theme switch (auto, light, dark) as icons only, always on the right
   of the header's title.
3. The test mode at its own route, `/test/`, linked from the footer.

## Done

- **Header** (`src/App.html`, `src/style.css`): the title and, on its right
  at every width, the theme switch as three icon buttons (half-filled
  circle, sun, moon; `aria-label` Auto, Light, Dark, a `title` each) and a
  settings button (sliders icon). The tagline takes the whole width under
  them; the title scales with the viewport (`clamp`) and the icons and
  gaps shrink under 24rem, so 320 px phones fit without overlap or
  horizontal scroll (at least 21 px to spare with Inter, DejaVu Sans or
  Liberation Sans, the fonts CI's browsers may use).
  The brand links to `/`.
- **Test mode page**: `test/index.html` (`<body data-page="test">`), a
  third Vite input next to the tester and the privacy page. `main.ts` picks
  the mode from the page; the Tester / Test mode tabs are gone, and the
  footer links the other page ("Test mode" or "Tester") next to
  "Privacy". The test page loads the test mode's module at start (W9: the
  tester never loads it) and has its own "Connect a pad with WebHID"
  button; a pad already granted on `/` reopens on its own (`getDevices`).
- **Settings dialog** with the sending switch (`src/sync.ts`): off by
  default, kept in `localStorage` (`anygamepad.sync`) while on, and
  disabled with "Not available yet: the database is not running" while the
  build names no database. `ANYGAMEPAD_SYNC_URL` at build time names one
  in a `<meta name="anygamepad-sync">` tag and adds its origin to the CSP's
  `connect-src` (https only; http for localhost).
  - With sending on: the activity log goes in parts
    (`POST <url>v1/activity-logs`): at once, then every 30 s with new
    events, 2,000 events per part at most, and a last part with
    `keepalive` when the page is hidden or goes away. Each part carries the
    page, the environment, a random ID of the page load, the part number,
    the UTC day, `dropped_input_events` and the events (times from the page
    load; no `started_at`). A failed part is sent again with the next one.
  - Saving a test report also sends it as downloaded
    (`POST <url>v1/test-reports`); the button reads "Save and send" and the
    note says whether it was sent. No cookies, no referrer.
  - `ActivityLog.unsent()` / `markSent()` track what was sent with
    absolute input counts, so the dropping of old input events cannot
    shift the cursor; `toJSON()` shares the merge.
  - Escape closes the settings and the share dialog.
- **Tests**: `smoke.mjs` checks the icons (no text), the title and the
  tools side by side at 1280, 360 and 320 px with the brand clear of the
  icons and no horizontal scroll, and the settings' disabled switch.
  `smoke-test-mode.mjs` reaches `/test/` from the footer (the tester never
  fetches the test mode's module), turns sending on against a fake
  database (Playwright adds the `<meta>` tag and answers `/__sync/`):
  first part with `session`, `page_visible`, `sending`, no cookie or
  referrer; the saved report sent equals the downloaded one; after a
  reload the choice holds and a new page load sends part 0 under another
  ID. The WebHID Quick plan now runs on the test page with a fake
  DualSense already in its full report (`__hid.fullReport`).
- Docs: `apps/web/README.md` (pages, sending, layout), the sync texts and
  the new storage key in `docs/privacy/README.md`, status notes in
  ROADMAP/2026-11-01 (README, W9, P6).
- Checked: `tsc`, build, size, both smoke tests in Chromium. Firefox and
  WebKit run in CI.
- Size (gzip): JS 79.8 of 80 KiB (77.5 before: +2.3 KiB, the settings,
  the icons and `sync.ts`), CSS 4.3 of 16, `.wasm` unchanged.

## Decisions

- The test mode is a separate HTML page, not client-side routing. Reason:
  GitHub Pages serves `/test/index.html` for `/test/` with no 404
  fallback; the page shares the app and its bundle, and only the
  `data-page` attribute differs.
- The sending switch exists before the server, but cannot be turned on
  until a build names one. Reason: the owner asked for it now, and the
  privacy policy promises nothing leaves the browser; the production build
  names no database until the server rules and the policy page cover what
  it stores (`docs/privacy/README.md#sync-p6`).
- Activity logs go in parts, not as one file. Reason: a page can close at
  any time and `keepalive` bodies are capped at 64 KiB; parts joined by a
  random ID per page load lose at most the last 30 s and link nothing
  across visits.
- Test reports are sent when saved, not when the session ends. Reason: the
  summary's review asks the person to edit device names out first; saving
  is their action.
- The settings button sits after the theme switch, both on the title's
  right. Reason: the owner asked for the theme there; the settings are
  where people look for them, and the icons fit beside the title on a
  320 px phone.

## Open questions

- **Where the database runs (owner decision).** Advice given on
  2026-11-02: a Cloudflare Worker written in Rust (`workers-rs`) with D1
  (SQLite) storage. It validates with the same `anygamepad-report` crate
  (already built for `wasm32`), needs no server to maintain, has a free
  tier far above this volume, rate limiting without storing addresses,
  and D1's point-in-time restore matches the 30-day backups of the server
  rules. The cost is SQLite instead of ADR 0006's PostgreSQL (curation can
  query an export) and some lock-in (the API is ours, the data exports).
  The alternative is ADR 0006 as written: `axum` and PostgreSQL on a
  small VPS, with backups, TLS and monitoring to run (P5). Choosing the
  Worker needs a new ADR that supersedes ADR 0006's storage and hosting.
- Retention of sent activity logs, and how a person withdraws them
  (deletion tokens per page load?), for the server rules.
- The JS budget has 0.2 KiB left: the next addition raises it, with its
  reason here or in its own RECORD.
