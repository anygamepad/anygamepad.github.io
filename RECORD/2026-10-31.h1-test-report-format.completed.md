# H1: Test report format

- Status: completed
- Roadmap: ROADMAP/2026-10-31/ (task ID: H1)

## Goal

The document every test mode writes (ADR 0008): the device under test,
the configuration the person confirmed and what detection proposed, the
plan, a result per step and the input recorded during each step;
anonymous by construction.

## Done

- `anygamepad_report::test_report`: `TestReport` (format
  `anygamepad-test-report`, version 1, the embedded device report
  `device`, `configuration`, `plan`, `results`, `notes`), `Configuration`
  (`start`: `list` or `connecting`, `confirmed` and `detected`
  `Selection`s: unit `Code`, model, mode, mode kind, transport;
  `detection_differs`), `PlanRef`, `StepResult` (step, check, `status`,
  expected, observed, `answer`, measurements, duration, note, `evidence`),
  `Evidence` (`frames` of raw states, `reports` of input reports, with
  `Millis` times from the step's start), `Summary`.
- Anonymity: `scrub` (device report scrubbed, OS version cut by
  `anonymous_os_version`, `user.product` emptied, notes and values
  scrubbed line by line, identifying input reports dropped from the
  evidence), `validate` (rejects all of these, plus malformed IDs,
  duplicate steps, non-finite measurements, evidence not sized for the
  first view or out of time order, over the limits), `review` (every
  text, device names the catalog and the family rules do not know for the
  model flagged `unknown_device_name`).
- `privacy::Finding` gains `os_version_detail` and `free_text` (the wasm
  bindings map them).
- JSON (`json` feature): `from_json`, `to_json`, `to_json_pretty`, 4 MiB
  limit (`MAX_TEST_REPORT_BYTES`); `file_name`; JSON Schema (`schemars`).
- `data/test-reports/`: README (contents, anonymity, size, CC0),
  `schema.json`, `example.json` (a Quick session on a DualSense through
  the Gamepad API). The web build publishes `/schema/test-report.json`.
- Tests (`tests/test_report.rs`): schema and example up to date, JSON
  round trips (web and desktop), file names, OS version cutting, scrub
  (Windows version with a name, `user.product`, notes with an address and
  an email, Nintendo `0x21` reply in the evidence), 18 kinds of invalid
  report rejected, notes keep their lines, the review flags a renamed
  pad, the schema rejects what the types reject, a Full session fits.
  Checked: fmt, clippy (workspace; report with all features, native and
  wasm32), rustdoc with `-D warnings`, tests, Rust 1.85.

## Decisions

- A test report embeds a device report rather than repeating its fields.
  Reason: the day, app, host and API views are already there, with their
  privacy rules; one source of truth.
- `user.product` must be empty in a test report. Reason: it is free text
  and the configuration already says what the pad is.
- Linux OS versions keep only the kernel's version numbers; elsewhere the
  version keeps letters, digits, dots and spaces up to the first other
  character. Reason: a custom kernel release can carry any text, and
  Windows' `23H2` is worth keeping.
- Evidence: input reports only when the API reads HID, raw states
  otherwise (documented on `Evidence`, applied by H3). Reason: states
  follow from reports by decoding, and keeping both doubles the size.
  Measured: a Full session of 45 steps of 1.2 s is about 2.2 MB from a
  250 Hz HID pad, 0.8 MB from the Gamepad API at 60 frames per second.
- Size limit 4 MiB as compact JSON. Reason: room for a Full HID session,
  small enough to commit the reports the lab keeps.
- Times as `Millis` (microseconds inside, milliseconds in JSON). Reason:
  exact comparisons and hashing, readable JSON.
- Step and check IDs are lowercase ASCII words (dots in step IDs); values
  are ASCII. Reason: the runner writes them; anything else is a bug or
  free text.
