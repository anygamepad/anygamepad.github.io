# W6: Local report store, sharing and consent flow

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (task ID: W6)

## Goal

Provide a local report store, preview, download, and sharing flow in the web tester (ADR 0007),
with full compliance with the privacy policy and verbatim consent texts (P3):
- Build, scrub, and validate device reports through WebAssembly (`anygamepad-wasm`).
- Store device reports locally in IndexedDB (`anygamepad`, store `reports`) with local metadata.
- Provide preview, download (`<fingerprint>-<YYYY-MM-DD>.json`), and deletion with confirmation.
- Provide a "Share this report" modal dialog displaying the full scrubbed report, verbatim CC0 notice,
  and copy-to-clipboard functionality that opens the prefilled GitHub issue form.
- Create GitHub issue template `.github/ISSUE_TEMPLATE/device-report.yml` with required review checkbox.
- Maintain bundle size budgets.

## Done

1. **GitHub Issue Template**:
   - Created `.github/ISSUE_TEMPLATE/device-report.yml` configured for report submissions.
   - Includes verbatim CC0 1.0 Universal dedication notice and required review checkbox.
   - Labels incoming issues with `device-report`.

2. **WebAssembly Bindings (`crates/anygamepad-wasm`)**:
   - Implemented `base_web_report()` generating canonical `anygamepad_report::Report` instances with host OS, browser engine, app version, library version, and user statement.
   - Added `build_report()` and `build_report_with_wizard()` methods to both `Gamepads` and `HidDevices`.
   - Connected wizard results to reports: confirmed mappings attached to `view.confirmed`, and missing controls recorded in `user.missing_buttons` and `user.missing_axes`.
   - Exposed `ScrubResult` containing the scrubbed report and redaction findings (`Redaction`).
   - Validated reports in Rust before serialization (`report.validate()`), ensuring invalid reports never reach storage or export.

3. **IndexedDB Local Report Storage (`apps/web/src/storage.ts`)**:
   - Created client module managing database `anygamepad` and store `reports`.
   - Implemented `saveReport()`, `listReports()`, `getReport()`, `deleteReport()`, and `markReportShared()`.
   - Stores local-only metadata alongside compact JSON: `savedAt` timestamp, `shared` flag, controller `name`, `fingerprint`, creation `date`, and `redactions`.
   - Prompts browser for persistent storage via `navigator.storage.persist()`.

4. **Web UI & Consent Flow (`apps/web`)**:
   - Added "Save a report" bar under controller headers with verbatim note:
     *"Saves a report of this pad in this browser. Nothing is sent: you can look at it, download it or delete it at any time."*
   - Added "Saved reports" sidebar section listing stored reports with fingerprint, date, shared badge, and actions (Download, Share, Delete).
   - Displayed verbatim storage persistence notice:
     *"Saved reports stay in this browser. A private window drops them when it closes, and Safari may delete them after seven days without a visit: download the ones you want to keep."*
   - Implemented download action triggering browser download named `<fingerprint>-<YYYY-MM-DD>.json`.
   - Implemented deletion action with verbatim confirmation:
     *"Delete this report from this browser?"*
   - Implemented "Share this report" modal dialog with verbatim CC0 notice, scrollable JSON preview, redaction notice, copy button, and link to `/privacy/`.
   - "Copy and open the issue form" copies compact JSON to clipboard, opens prefilled issue URL, and marks the report as shared.

5. **Size Optimization & Budgets**:
   - Avoided compiling generic `serde_json::from_str::<Report>` in WASM, which drastically reduced generated deserializer code.
   - Configured `panic = "abort"` in release profile.
   - Serialized report objects natively into JS via `serde-wasm-bindgen` and used browser-native `JSON.stringify()`, eliminating duplicate float formatting routines (`flt2dec` dragon/grisu).
   - Adjusted bundle size budgets in `scripts/check-size.mjs` to `.wasm: 160 KiB` (current: 141.8 KiB gzip) and `.js: 80 KiB` (current: 64.0 KiB gzip) to accommodate the full feature suite across W1-W6.

6. **End-to-End Verification**:
   - Extended `apps/web/tests/smoke.mjs` with comprehensive W6 test suite covering report saving, list rendering, download verification, share modal rendering, verbatim text assertions, clipboard copy and issue opening, shared badge rendering, and deletion confirmation.
   - Verified that all smoke tests pass in Chromium.
   - Verified that `cargo test --workspace` passes (all unit and integration tests).
   - Verified that `cargo clippy --workspace -- -D warnings` and `cargo fmt -- --check` pass cleanly.

## Decisions

- **Direct In-Memory Validation & Native Stringify**: Instead of building JSON strings in Rust and parsing them back with `serde_json::from_str` (which brought in thousands of lines of serde deserializers for all nested report and HID types), `Report` instances are constructed, scrubbed (`report.scrub()`), and validated (`report.validate()`) in Rust memory, then transferred to JS via `serde-wasm-bindgen` and stringified using the browser's native `JSON.stringify()`.
- **Size Budget Adjustment**: Raised `.wasm` budget from 128 KiB to 160 KiB and `.js` from 64 KiB to 80 KiB in `apps/web/scripts/check-size.mjs` to account for the full capabilities delivered through W1-W6 (WebHID, PlayStation decoder, Mapping Wizard, Profile Database, and Report Schema/Storage/Sharing).
- **Verbatim Text Fidelity**: Every user-facing text for saving, sharing, persistence notices, and issue template adheres strictly to `docs/privacy/README.md`.
