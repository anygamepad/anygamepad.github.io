## Decisions

- The firmware check runs on a click, never by itself. Reason: over
  Bluetooth, reading a feature report switches the pad to its full
  report for every application until it is turned off (research note
  09); the person decides.
- A pad that does not answer is "most likely a compatible pad", not a
  fake, and only reorders the candidates. Reason: the check is a
  heuristic (C8's job, as profiles and data grow); the person confirms.
- The firmware result is not written into the test report yet. Reason:
  the test report format (H1) has no field for it; adding one changes
  the schema, which waits for C8's needs.
- The touchpad click comes from a profile, not from code in the standard
  layout. Reason: profiles are where devices are described (D1, D4), and
  this one is verified by PAD-01's report.
- The generic PlayStation model's mode follows the family the name
  tells. Reason: macOS names PAD-01 a DualSense, so PS5 is what it
  imitates there; the person can still pick PS4.
- Home on macOS: a note in the web, the system gesture turned off in the
  desktop provider. Reason: a web page cannot ask macOS to leave the
  button alone; an app can, while it is the active one.
