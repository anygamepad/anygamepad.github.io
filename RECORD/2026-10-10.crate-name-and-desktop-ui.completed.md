# Crate name and desktop UI direction

- Status: completed
- Roadmap: ROADMAP/2026-10-10/ (re-planned in place, same day; F1, F3, A1,
  new task A11)

## Goal

Apply the owner's choice of crate name and the desktop UI requirements.

## Done

- Crate name `omnipad` chosen by the owner; crates renamed `omnipad-*` in the
  roadmap. `omnipad` and `omnipad-wasm` were free on crates.io, and `omnipad`
  on npm, on 2026-10-10. The repository/project keeps the name rustpad.
- F1 now reserves the names with placeholder releases.
- Desktop UI ADR (F3 item 4) rewritten around the owner's requirements:
  performance first and an always-on-top widget. Recommendation changed from
  Tauri 2 to egui (`eframe` + `wgpu`), to be validated with a prototype.
- New task A11 (always-on-top input widget, blocked by A2, blocks A9). Not on
  the critical path (5 days of slack).
- New risk: Wayland has no standard always-on-top for regular windows, and
  exclusive full-screen games cover any window.
- AGENTS.md: crate name and desktop UI requirements.
- Mermaid diagrams validated with mermaid-cli.

## Decisions

- Crate name `omnipad` (owner decision). Reason: `rustpad` is taken on
  crates.io. *Superseded by
  `2026-10-10.rename-crates-to-anygamepad.completed.md`: `omnipad` is taken on
  GitHub, crates are now `anygamepad`.*
- Desktop UI: egui recommended over Tauri. Reason: the owner prioritizes
  performance; egui runs in-process with the library (no webview, no IPC),
  repaints on demand, and supports separate always-on-top, transparent,
  click-through windows via winit. Tauri's webview costs memory/CPU and
  transparent overlays are fragile on Linux. Consequence: the desktop app no
  longer dictates the web frontend framework.
