# C4: Linux input backend (evdev)

- Status: WIP
- Roadmap: ROADMAP/2026-10-14/ (task ID: C4)

## Goal

The native provider on Linux: evdev for devices bound to kernel drivers,
hotplug, documented permissions; hidraw for devices anygamepad drives
itself.

## Done

- `anygamepad::native::evdev` (sans-IO, builds on every OS): node
  classification from capabilities (gamepad, motion, touchpad, other),
  sysfs bitmap parsing, `GamepadNode` (layout of `RawSource::Evdev`
  buttons, axes with their ranges, hats; fills a `RawState`),
  `MotionNode` (accelerometer and gyroscope to SI units with the axis
  resolutions, `MSC_TIMESTAMP` clock with wrap-around), `TouchpadNode`
  (multitouch protocol B slots, click), `transport()` from the bus type,
  `spec_mapping()` for drivers that follow the Linux gamepad specification
  (`SPEC_DRIVERS`: xpad, playstation, nintendo, sony).
- `anygamepad::native::linux::LinuxProvider` (`Provider`): sysfs
  discovery without opening non-gamepad nodes, a controller's nodes
  grouped by sysfs parent into one device (gamepad + motion + touchpad,
  touchpad click as `button:touchpad_click`), identity (VID/PID/version,
  name, bus, driver, HID descriptor hash from sysfs), shared, exclusive
  (`EVIOCGRAB`) and observe-only access, polling through the `evdev`
  crate's synced state (handles `SYN_DROPPED`), rumble through force
  feedback, removal on `ENODEV`, `inaccessible()` count.
- Feature `native` (default) in `anygamepad`; `evdev` 0.13.2 only on Linux.
- `examples/linux_pads.rs`: lists pads, prints canonical state, rumbles on
  south.
- `docs/linux-permissions.md`.
- Tests: classification, bitmaps (64 and 32-bit words), layout and fill,
  spec mapping through the mapping engine (DualSense and Switch Pro
  layouts), motion, touch slots, a fake sysfs tree (grouping, keyboards
  skipped), error mapping. Clippy (default, no default features, wasm32),
  workspace tests, `cargo +1.85 check`; web bundle 141.2 KiB gzip.

## Decisions

- Hotplug by listing sysfs every 500 ms instead of libudev or inotify.
  Reason: no C library (the `udev` crate links libudev), no extra thread,
  and the cost is a directory listing; a device is reported once two scans
  see it, which also covers udev setting permissions after the node
  appears.
- Classify from sysfs before opening. Reason: never open keyboards or
  mice (privacy), and no permission is needed to look.
- Raw evdev sources plus `spec_mapping()` rather than canonical sources
  in the provider. Reason: profiles (D4) stay able to correct a driver;
  the spec mapping is the default for drivers known to follow it.
- Never read `uniq` or `phys`. The `evdev` crate reads them when opening
  a node; anygamepad never calls its accessors.
- Motion axes taken as the canonical frame (SDL's, which the drivers
  follow). Not checked on a device.
