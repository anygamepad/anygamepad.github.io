# A2: Device list and live view

- Status: WIP
- Roadmap: ROADMAP/2026-10-14/ (task ID: A2)

## Goal

List detected devices with identity (C2), detected mapping/profile, live
canonical input and raw input side by side. Linux first, Windows and
macOS as their backends (C5, C6) land.

## Done

- `apps/desktop/src/devices.rs`: a worker thread owns the provider, opens
  every device (shared access), maps it (database profile, else the Linux
  gamepad specification for drivers that follow it, else canonical
  sources, else raw only), polls every 4 ms while a device is open and
  every 100 ms otherwise, publishes a snapshot and wakes the UI only when
  something changed; the UI sends output commands back over a channel.
- `apps/desktop/src/devices_page.rs`: the controller list (name, VID/PID,
  connection), a permission warning with the count of unreadable pads,
  and per device: identity (VID/PID, connection, driver, mapping source,
  element counts, battery), rumble test, canonical view (sticks drawn,
  triggers, buttons) and raw view (every element by its source, axes over
  their range, hats, latest motion sample, touchpad).
- `Provider::inaccessible()` (default 0) in the library; the Linux
  provider implements it.
- `ANYGAMEPAD_DEMO=1`: a made-up pad that moves by itself, to try the app
  and for tests.
- Checked under Xvfb (software rendering): with no pad, 2 ticks of CPU in
  10 s; with the demo pad changing 20 times a second, about half a core,
  which is llvmpipe drawing each frame. Screenshot taken. Tests: mapping
  sources, the worker publishing the demo pad.

## Decisions

- One worker thread for all devices, the UI reading snapshots. Reason:
  polling never waits on drawing, and the window repaints only on change.
- Devices are opened in shared access: the app reads without hiding pads
  from games; exclusive access belongs to the virtual pad (A5/A6).
