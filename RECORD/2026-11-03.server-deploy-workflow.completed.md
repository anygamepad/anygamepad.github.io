# Deployment of the sync server from GitHub Actions

- Status: completed (the owner runs it)
- Roadmap: ROADMAP/2026-11-01/ (task ID: P5)

## Goal

The owner asked on 2026-11-03 for help deploying the sync server
(`apps/server`, ADR 0009) to Cloudflare. The agent's environment cannot
reach `api.cloudflare.com` (its network policy denies the host) and holds no
Cloudflare credentials, so the deployment has to run elsewhere.

## Done

- `.github/workflows/deploy-server.yml`, run by hand (Actions, "Deploy
  server"): checks the repository secrets `CLOUDFLARE_API_TOKEN` and
  `CLOUDFLARE_ACCOUNT_ID`; finds the D1 database `anygamepad-sync` by name
  (`wrangler d1 list --json`) or creates it in the EU jurisdiction (from an
  empty folder, so wrangler leaves `wrangler.toml` alone) and writes its id
  into `wrangler.toml` for the run; applies the migrations; deploys (the
  build is wrangler.toml's `worker-build`); makes `RATE_LIMIT_KEY` at random
  when the Worker has none (`wrangler secret list`); waits for `GET /` to
  answer as `anygamepad-sync`; and writes the URL and the next step (the
  repository variable `ANYGAMEPAD_SYNC_URL`) in the run's summary.
- `build.yml`: a run by hand of "Build" on `main` also publishes the site to
  GitHub Pages, so setting `ANYGAMEPAD_SYNC_URL` takes effect without a
  push. Releases, which call `build.yml` as "Release", still do not publish.
- `apps/server/README.md`: deployment from GitHub Actions (the Cloudflare
  token and its permissions, the secrets, the run, the variable, the DPA)
  and from a computer; `wrangler.toml`'s comment on the database id.
- Checked: actionlint with shellcheck on both workflows; the jq filters, the
  `sed` on `wrangler.toml` and the URL extraction on sample outputs;
  `wrangler deploy --dry-run` builds the Worker (229 KiB gzip) with its
  bindings (`DB`, `UPLOADS`, the two variables). Not run against Cloudflare:
  that is the owner's first run.

## Decisions

- **GitHub Actions, not this environment.** Reason: the token stays a
  repository secret the agent never sees, later deployments are one click,
  and the agent's network cannot reach Cloudflare anyway.
- **By hand only, not on every push to `main`.** Reason: a deployment
  changes a live service holding people's data; the owner decides when.
- **The database id is not committed**: the workflow looks it up by name.
  Reason: no commit after the first run; a deployment from a computer can
  still write it into `wrangler.toml`.
- **The rate limiter's key is made by the workflow**, not a GitHub secret.
  Reason: nobody needs to know it, and replacing it only restarts counters.
