# Roadmap 2026-10-14: W3 with PlayStation decoding

- Status: completed
- Roadmap: ROADMAP/2026-10-14/ (task IDs: C15 new; C6, C7, W3 changed)

## Goal

The owner asked to prepare the roadmap for W3 after the first real-device
test: a DualSense that the Gamepad API never exposes in Chrome on macOS, and
that WebHID can read. Re-plan so W3 can decode PlayStation pads.

## Decisions

- C15 is a new task rather than a re-scoped C7. Reason: C7 waits for C4
  (Linux backend) while the input decoder needs no backend; task IDs stay
  stable within a version, and a new ID keeps C7's history readable.
- W3 stays off the M2 path (it blocks nothing). Reason: the web launch does
  not need WebHID; the owner wants it next for testing, which the README
  records as a decision with its cost.
- In the master Gantt, tasks come after their blockers, and the core library
  and device database share one section. Reason: Mermaid resolves `after x`
  only against tasks defined above. The 2026-10-10 master Gantt drew C3, A1
  and A4 too early and M4 in December because of this; the per-file charts
  were right.
- Tasks whose blockers are all done also wait for `t0`. Reason: otherwise
  Mermaid starts them in the past, at their blockers' actual end.
- Storage direction recorded, not re-planned. Reason: it changes the
  collection pipeline and the critical path; it needs an ADR first.
